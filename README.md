# ok-filemanager

**Файловый менеджер для ОК** — кроссплатформенный (приоритет — Windows)
помощник для работы с треками и путевыми точками (`.gpx`, `.plt`,
`.wpt`). Интерфейс — **GUI на PySide6 (Qt 6)**.

Умеет:

- переименовывать файлы из «скачанных» имён в формат `ГГГГММДД_Позывной`
  с нормализацией позывного;
- создавать локальные папки прямо из дерева файлов;
- переносить локальные файлы между папками;
- копировать имя выделенного элемента в буфер;
- синхронизировать статус «уже на FTP» между локальной папкой и сервером;
- просматривать, обновлять и удалять файлы на FTP-сервере;
- загружать файлы на FTP-сервер;
- следить за изменениями директории (watchdog, автообновление);
- работать в светлой или тёмной теме, включая автоопределение системной.

---

## Возможности

### Современный интерфейс

- Оформление на Qt-стиле **Fusion** с кастомным QSS: скруглённые панели,
  акцентные кнопки, hover-эффекты, подсветка активной вкладки,
  состояния `disabled`/`focus`/`pressed`, собственные шеврон списка и
  отметка чек-бокса (без внешних ресурсов).
- Палитра на холодных нейтралях, отдельные тона для рамок полей и
  разделителей; светлая и тёмная темы согласованы по контрасту.
- Верхний toolbar с иконками и текстом; набор кнопок зависит от
  активной вкладки:
  - **Файлы** — Вверх, Обновить, Исправить все, Папка,
    Переименовать, Переместить, Копировать имя, На FTP,
    В проводнике, В OziExplorer, Проверить загрузки;
  - **FTP** — Подключиться, Обновить, Копировать имя,
    Загрузить сюда…, Удалить.
  Кнопка «Журнал» общая для обеих вкладок. Иконки — системные глифы
  Qt, дополнительных файлов ресурсов проект не требует.
- При сужении окна кнопки шапки переносятся на следующую строку, а не
  прячутся в меню «>>», — все действия остаются на виду.
- Меню (Файл / Правка / FTP / Вид / Справка) с горячими клавишами и
  иконками.
- Панель журнала — **сворачиваемый док внизу окна**; журнал можно
  скрыть (**Ctrl+L**), состояние и высота запоминаются.
- Статусбар: сообщение о текущей операции слева, счётчики файлов,
  ошибок и заливок плюс корень дерева — справа.
- Размеры и положение окна, высота журнала и ширины колонок
  сохраняются в конфиге при закрытии окна.
- Предсказуемые отказы (не тот формат файла, нет папки) показываются
  неблокирующей плашкой над содержимым; `blocking_errors = true`
  возвращает модальные окна.
- Цветные статусные пометки прямо в дереве.
- Тема интерфейса: `auto / light / dark` (F10 → **Интерфейс**). `auto` на
  Windows читает системную из реестра (`AppsUseLightTheme`).
- Мелкие элементы темы (галочка чек-бокса, стрелки раскрытия папок и
  выпадающих списков) рисуются в PNG при первом запуске темы и
  кладутся в `icons/` рядом с конфигом. Qt не умеет читать `data:`-URI
  в таблице стилей, поэтому картинки именно файловые; без прав на
  запись используется временный каталог, а при полном запрете записи
  интерфейс работает без этих отметок.

### Дерево файлов

- Рекурсивное дерево с ленивой подгрузкой.
- Двойной клик по папке — раскрыть / свернуть.
- Двойной клик по файлу — контекстное меню с доступными действиями
  (Открыть, Переименовать…, Переместить…, Копировать имя), «Копировать
  путь» и «Показать в проводнике»; файл открывается системным
  приложением пунктом «Открыть». Пункт «На FTP» показывается только
  у файлов, прошедших проверку — тех, что в дереве помечены
  «можно на FTP». Для файлов `.kmz` доступен пункт **KMZ → KML**,
  для `.gpx` / `.kml` / `.plt` / `.wpt` / `.map` — **Открыть в
  OziExplorer**.
- Enter на папке — сделать её корнем дерева.
- Переходы по дереву (Enter, «Вверх», «Обзор…») меняют только
  отображаемый корень: корневая папка из настроек (`root_dir`) при
  этом не переписывается и задаётся в F10.
- Правый клик — контекстное меню.
- «Показать в проводнике» (**Ctrl+E**) открывает системный файловый
  менеджер с выделенным элементом: на Windows — Проводник
  (`explorer /select,"путь"`), на macOS — Finder, на Linux — папка
  через `xdg-open`. Кавычки ставятся только вокруг пути: если путь с
  пробелами уйдёт одним аргументом, Проводник не распознаёт ключ
  `/select` и открывает «Документы».
- Автообновление при изменениях на диске.
- Выделение не теряется при перестройке дерева (watchdog, перенос,
  правка имени, загрузка на FTP): действия на панели инструментов
  работают по выбранному файлу сразу после одного клика. После
  переименования выделение переходит на новое имя.
- Цветовые пометки: папки — оранжевые; ошибки — красные; уже залитые
  на FTP — зелёные, со пометкой `✓ на FTP`. Для `.kmz` в колонке
  «Статус» выводится подсказка «можно конвертировать в .kml» (действие
  **KMZ → KML** в контекстном меню).

### Журнал

- Показывает операции, предупреждения и ошибки с отметкой времени.
- Панель внизу окна: длинные записи переносятся с висячим отступом, а
  не уезжают под колонку времени.
- Прокручивается вниз только если вы уже внизу — чтение истории не
  срывается новыми записями.
- Кнопки панели: «Копировать журнал» (**Ctrl+Shift+L**), «Сохранить в
  файл…» (`Правка → Сохранить журнал в файл…`) и «Очистить».
- Панель скрывается кнопкой «Журнал» в toolbar или **Ctrl+L**.

### Создание папок

- **Ctrl+N** — открыть диалог.
- **В корне** (совпадает с `root_dir` из настроек): имя
  предзаполняется текущей датой `ГГГГ-ММ-ДД_`; доступен чек-бокс
  `Создать внутри 10-Tracks`.
- Во вложенных папках поле имени пустое, чек-бокса нет.
- `Ctrl+T` в поле — транслит на латиницу.

### Перенос файлов между папками

- **Ctrl+X** — открыть диалог.
- В диалоге — дерево папок для навигации; двойной клик — войти,
  `↑ Вверх` — выйти, кнопка `Переместить сюда` — выполнить перенос.
- Работает только для локальных файлов.

### Переименование

- **F2** — открыть диалог: «Было», «Предложение» (автоправка), поле
  ввода с предзаполнением.
- `Ctrl+T` — транслит + нормализация позывного.

### Копирование имени (Ctrl+Y)

- В дереве «Файлы» — имя файла (без расширения) или имя папки.
- В списке FTP — имя файла (без расширения) или имя папки-объекта
  на сервере.

### Распаковка KMZ в KML (KMZ → KML)

Пункт «KMZ → KML» в контекстном меню файла `.kmz` (правый клик или
двойной клик) повторяет ручной сценарий:

1. делается копия `.kmz` с расширением `.zip`;
2. из архива извлекается файл `.kml` и называется так же, как
   исходный `.kmz`;
3. промежуточная копия `.zip` удаляется — остаются только `.kmz` и
   `.kml`.

Если `.kml` с таким именем уже есть, спрашивается подтверждение на
перезапись.

### Открытие в OziExplorer

Кнопка **«В OziExplorer»** на панели (вкладка «Файлы», **Ctrl+Shift+O**)
и пункт **«Открыть в OziExplorer»** в контекстном меню файлов
`.gpx` / `.kml` / `.plt` / `.wpt` / `.map` открывают выделенный файл в
OziExplorer 3.95:

1. если доступна `OziAPI.dll` — файл грузится в **уже открытое окно**
   через API (`oziLoadWPfile`, `oziLoadTrackFile`, `oziLoadMap`), без
   второго окна. Если OziExplorer ещё не запущен, программа запустит его
   сама и дождётся готовности API: окно появляется сразу, а команды
   начинают проходить секунд через восемь (в журнале видно, что идёт
   ожидание);
2. если DLL нет — `.map` открывается запуском `oziexp.exe` в новом окне
   (карта грузится и так), а `.plt`, `.wpt`, `.gpx` и `.kml` в открытое
   окно отдать нечем: программа скажет об этом прямо, потому что запуск
   exe эти файлы не грузит.

**GPX и KML.** Загрузчиков таких файлов в OziAPI нет (на `.gpx`
`oziLoadTrackFile` отвечает модальным «Invalid numeric input.»),
поэтому программа разбирает их сама (`ok_helper/gpxkml.py`) и отдаёт
OziExplorer обычными `.plt`/`.wpt`: треки пишутся во временные `.plt`
и грузятся `oziLoadTrackFile` в выбранный слот (и следующие за ним —
треков в файле может быть несколько), точки — во временный `.wpt`.
Переносятся координаты, высота (в файлах OziExplorer она в футах —
пересчитывается) и время как записано, без пересчёта часового пояса.
Битый KML разбирается мягко, поиском по тексту: OziExplorer пишет свои
KML с незакрытым `<Folder>` и собственными `<end>`, строгий XML их не
принимает. Имя трека в OziExplorer — имя файла (для файла с несколькими
треками — с номером, имена внутри GPX/KML бывают служебными). Копии
пишутся в `%LOCALAPPDATA%\ok-filemanager\import` и **не удаляются**:
OziExplorer запоминает имя файла трека и восстанавливает трек из него.
Загрузка идёт одним вызовом на трек — даже трек на 7–8 тысяч точек
грузится мгновенно (замер: 0,2 с на 7662 точки), а добавление точек
`oziCreateWPex` медленное: им пользуются только для «добавить точки».

Требования для API-режима: `OziAPI.dll` и OziExplorer ≥ 3.95.2.
**Отдельно включать API в OziExplorer не нужно** — такой настройки ни в
Configuration, ни где-либо ещё нет (проверено по справке
`OziExplorer.chm` от 3.95.6f: `OziAPI` упоминается там только в истории
версий).

**Место загрузки выбирается.** Когда файл идёт в уже открытое окно,
программа спрашивает, **куда** его грузить, — иначе каждый следующий
файл затирал бы предыдущий:

- для `.plt` — номер трека (1–75). Загрузка в занятый номер затирает
  лежавший там трек, поэтому по умолчанию предлагается текущий номер, а
  после успешной загрузки — следующий (`ozi_track_num` увеличивается
  на число загруженных треков). Заодно включается показ треков: кроме
  трека 1, OziExplorer держит треки скрытыми, и загруженный трек иначе
  не видно;
- для `.wpt` — «добавить к загруженным точкам» или «заменить
  загруженные». API умеет грузить файл точек только целиком
  (`oziLoadWPfile` заменяет набор), поэтому добавление идёт по точке
  (`oziCreateWPex`) и на больших файлах заметно медленнее — зато ничего
  не пропадает;
- для `.gpx`/`.kml` спрашивается и то, и другое — но только про то, что
  в файле есть: если треков нет, про номер трека не спрашивают.

В диалоге есть галочка **«Запомнить и больше не спрашивать»**: она
снимает соответствующий вопрос (`ozi_track_ask` / `ozi_wpt_ask`), и
следующие файлы грузятся с сохранённым выбором молча. Включить вопрос
обратно можно только в настройках (**F10 → OziExplorer**, галочки
«Спрашивать номер трека» / «Спрашивать режим точек») — там же задаются
номер трека и режим точек по умолчанию.

**OziExplorer многовконный.** Проверено на 3.95.6f: каждый запуск
`oziexp.exe` с файлом поднимает **новое** окно (три запуска — три
процесса `OziExp.exe`), Windows-ассоциаций файлов OziExplorer не
регистрирует, а официальная справка допускает в командной строке только
имя **карты** (треки и точки она не грузит). Ни single-instance, ни DDE
у него нет, поэтому попасть в уже открытое окно **без `OziAPI.dll`
невозможно**: `.map` откроется в новом окне, а `.plt`/`.wpt`/`.gpx`/
`.kml` загрузить не получится — об этом программа и сообщает.

**DLL поставляется в комплектном архиве.** `OziAPI.dll` не входит в
установщик OziExplorer, но её разрешено распространять с программой,
которая её использует (документация API: DLL должна лежать в папке
использующей её программы или на пути поиска Windows). Поэтому архив
`assets/oziapi_dll.zip` лежит в комплекте. **Сам по себе архив DLL не
заменяет** — его нужно распаковать кнопкой **«Распаковать OziAPI»**
в настройках (**F10 → OziExplorer**); тогда DLL появится в
`%LOCALAPPDATA%\ok-filemanager\OziAPI.dll`, а путь подставится в поле
«Путь к OziAPI.dll». Пока этого не сделали (и путь не указан), DLL
считается недоступной: `.map` откроется в новом окне, а `.plt`/`.wpt`/
`.gpx`/`.kml` в открытое окно отдать нечем. Порядок поиска
DLL: заданный путь → рядом с нашей программой (`OziAPI.dll`,
`lib/OziAPI.dll`, `assets/ozi/OziAPI.dll`) → распакованная копия →
папка `oziexp.exe`.

**Почему нужен отдельный процесс.** `OziAPI.dll` — 32-битная (как и сам
OziExplorer), а программа работает на 64-битном Python, который такую
DLL загрузить не может (`WinError 193`). Поэтому DLL загружает
поставляемый с Windows 32-битный PowerShell
(`%SystemRoot%\SysWOW64\WindowsPowerShell`), а программа общается с ним
через stdin/stdout; скрипт-мост — `ok_helper/ozi_api_bridge.ps1`.
Процесс-мост держится живым: первый вызов ~2–3 с (компиляция P/Invoke),
дальше — доли секунды.

Кнопка **«Скачать OziAPI»** в настройках (**F10 → OziExplorer**)
открывает страницу загрузки DLL — на случай, если комплектный архив не
подошёл.

Если DLL нет вовсе, `.map` всё равно откроется (запуском `oziexp.exe` в
новом окне), а остальные форматы в открытое окно не отдать — программа
скажет об этом прямо, а не откроет пустое окно.

Путь к `oziexp.exe` и `OziAPI.dll` задаётся в **F10 → OziExplorer**.
Пустое поле означает автоматический поиск: `PATH`, типовые папки
установки и реестр Windows для exe; для DLL — см. порядок выше.

### Папка загрузок

Слежение включается в F10 → **Папки** («Следить за папкой загрузок»)
или в меню **Загрузки** — там же ручная проверка (**Ctrl+D**) и
«Открыть папку загрузок».

- Когда в папке появляется новый `.gpx`, `.plt`, `.wpt`, `.kml` или
  `.kmz`, сервис предлагает перенести его в корень дерева или выбрать
  папку. Для `.kmz` остаётся доступно действие **KMZ → KML**.
- Если в открытой сейчас папке (корне дерева) есть **дочерняя** папка
  `10-Tracks` ровно на один уровень вложенности (`папка_а/10-Tracks` —
  да, `папка_а/папка_б/10-Tracks` — нет), перенос предлагается именно
  в неё. Если такой папки нет — прежняя логика: корень дерева или
  выбор папки вручную.
- Временные файлы браузеров (`.crdownload`, `.part`, `.tmp`,
  `.download`, `.partial`, `.opdownload`) готовыми не считаются:
  уведомление приходит после переименования в рабочий формат.
- Папка проверяется и по событиям файловой системы, и дополнительно
  каждые 3 секунды. События могут не дойти на сетевом диске, в
  OneDrive или после сна машины — периодическая проверка это
  закрывает, а `Ctrl+D` проверяет папку вручную.
- Файлы, скачанные до запуска сервиса, не предлагаются: иначе при
  каждом старте всплывало бы всё содержимое папки. Допуск в одну
  секунду — чтобы не потерять файл, скачанный в момент запуска.
- Состояние слежения всегда видно в журнале: включено (с путём),
  выключено или папка недоступна.

### Проверка и переименование имён

Для `.gpx` и `.plt` — формат `ГГГГММДД_Позывной`.

**Нормализация позывного:**

- первая буква — заглавная (`lisa` → `Lisa`);
- хвостовой номер (1–4 цифры после букв) — минимум 2 разряда,
  разделитель `_`/`-` перед ним убирается. Номер может быть как в
  конце, так и в середине:
  - `lisa_1` → `Lisa01`
  - `lisa1` → `Lisa01`
  - `lisa-1` → `Lisa01`
  - `lisa_12` → `Lisa12`
  - `Lisa_03_Test` → `Lisa03_Test`
  - `Lisa_04_1` → `Lisa04_1`
- если база уже оканчивается цифрой (`Lisa01_1`), хвостовая группа
  не трогается.

**Дата из содержимого `.gpx`.** Если в имени `.gpx` даты нет, сервис
читает последние ~256 КБ файла и берёт дату из последней `<time>`.

Для `.wpt` — только `Waypoints_ГГГГММДД`. Файлы `<1-4 цифры>m.gpx`
(`100m.gpx`) не проверяются.

### Работа с FTP

**Ссылка на папку.** На вкладке FTP под путём показывается ссылка
на корневую папку на сервере — гиперссылка вида
`{base_url}/{имя_папки}`; клик открывает её в браузере. Имя папки —
первый компонент пути (корневая папка). Адрес `base_url` задаётся
в настройках (F10); пока он пуст, показывается прочерк.

**Автоподстановка пути.** На вкладке FTP есть чек-бокс «Следить за
папкой из вкладки «Файлы»». Если включён, при переходе на вкладку FTP
сервис ищет вверх по дереву папку вида `ГГГГ-ММ-ДД_Место` от
выделенного элемента (или от корня, если ничего не выделено),
подставляет её в путь и загружает листинг.

**Синхронизация с локальной папкой.** После каждой загрузки листинга
папки на FTP локальные файлы с такими же именами (в папке с
совпадающим именем) помечаются зелёной галочкой `✓ на FTP`. Сверка
обновляется:

- при каждой загрузке листинга (кнопка «Обновить», двойной клик);
- после каждой успешной загрузки файла на FTP.

**Отправка (F12 или `⇪ FTP`):**

- `.plt` — с корректным именем;
- `.wpt` — только `Waypoints_ГГГГММДД`;
- `.gpx` — **только** `<1-4 цифры>m.gpx`;
- файлы из папки `10-Tracks` — запрещены;
- папка назначения обязательна.

**Удаление (Del во вкладке FTP):** только при `ftp_readonly = false`,
с диалогом подтверждения.

**Режим эмуляции.** `ftp_readonly = true` — сервис подключается,
читает папки, но **не создаёт**, **не загружает** и **не удаляет**
файлы.

## Установка

Требуется **Python 3.11+** и **PySide6**.

```bash
git clone https://github.com/<ваш-логин>/ok-filemanager.git
cd ok-filemanager
python -m venv .venv

# Windows (PowerShell):
.venv\Scripts\Activate.ps1

pip install -r requirements.txt
python main.py
```

Можно указать директорию сразу:

```bash
python main.py /path/to/tracks
```

## Настройка

Все настройки — в TOML-файле:

| ОС | Путь |
|---|---|
| Windows | `%APPDATA%\ok-filemanager\config.toml` |
| Linux | `~/.config/ok-filemanager/config.toml` |
| macOS | `~/Library/Application Support/ok-filemanager/config.toml` |

Правятся через **F10** (настройки разбиты на вкладки **Папки**,
**Интерфейс**, **FTP**, **OziExplorer**) или вручную. У полей-путей
(`root_dir`, `downloads_dir`, `ozi_exe`, `ozi_api_dll`) справа есть
кнопка **«…»** — выбор папки или файла в системном диалоге:

```toml
root_dir        = 'C:\Users\you\Tracks'
downloads_dir   = 'C:\Users\you\Downloads'
watch_downloads = false
theme           = 'auto'   # auto | light | dark

ftp_host        = 'ftp.example.com'
ftp_port        = 21
ftp_user        = 'username'
ftp_password    = 'secret'
ftp_path        = '/upload'
ftp_readonly    = false
base_url        = 'https://example.com/ftp'

ozi_exe         = 'C:\Program Files (x86)\OziExplorer\oziexp.exe'
ozi_api_dll     = 'C:\Program Files (x86)\OziExplorer\OziAPI.dll'
ozi_track_num   = 1        # номер трека (1..75) для следующей загрузки
ozi_track_ask   = true     # спрашивать номер трека перед загрузкой
ozi_wpt_mode    = 'append' # append | replace — что делать с точками
ozi_wpt_ask     = true     # спрашивать режим точек перед загрузкой

help_visible_at_start = true
first_run = false

# --- состояние интерфейса (пишется автоматически при закрытии) ---
window_geometry     = '1000,700,10,20'   # ШxВ+X+Y; пусто — по умолчанию
tree_column_widths  = '300,80,120'       # ширины колонок дерева
log_visible         = true               # показывать панель журнала
log_dock_height     = 180                # высота панели журнала, px
blocking_errors     = false              # отказы — плашкой, а не окном
```

Ключи состояния интерфейса можно удалить: тогда окно откроется с
размерами по умолчанию, а колонки снова станут «по содержимому».
Ключ `splitter_state` остался от версии с журналом слева: он больше не
используется и записывается пустым.

Пути пишите в **одинарных** кавычках, если они содержат `\`:

```toml
root_dir = 'C:\Users\you\Tracks'   # правильно
root_dir = "C:\Users\you\Tracks"   # ошибка TOML
```

## Разработка

### Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest -v
```

Маркеры: `analyzer`, `ftp`, `translit`, `folder`, `path_walk`, `upload`,
`clipboard`, `handlers`, `config`, `theme`, `gui`, `main`, `kmz`, `ozi`,
`wpt`, `smoke`.
Пример: `pytest -m "ftp and smoke"`.

GUI-тесты не требуют экрана: `conftest.py` выставляет
`QT_QPA_PLATFORM=offscreen`, а модальные окна, FTP-задачи и
watchdog-наблюдатели в тестах подменяются. FTP-клиент проверяется на
мини-эмуляции `ftplib.FTP`, поэтому реальный сервер не нужен.

### Сборка портативной версии

Локально:

```bash
pip install pyinstaller
pyinstaller --onefile --windowed --name ok-filemanager \
    --icon assets/ok-filemanager.ico \
    --add-data "ok_helper/ozi_api_bridge.ps1;ok_helper" \
    --add-data "assets/oziapi_dll.zip;assets" \
    main.py
```

`--add-data` кладёт в сборку мост к OziAPI и комплектный архив с DLL —
без них интеграция с OziExplorer в собранном `.exe` будет работать
только в режиме «новое окно».

Готовый `.exe` появится в `dist/`. Артефакт `ok-filemanager-windows` из
GitHub Actions содержит ту же сборку.
